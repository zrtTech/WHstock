# План полной миграции WHstock в Native Android (Android 6+, Kotlin/Java)

## 1) Цели миграции и границы совместимости

- Целевая платформа: **Android 6.0 (API 23)** и выше.
- Принцип: **feature parity** с текущей PWA/веб-версией и серверным контуром.
- Поддержка двух ролей и режимов:
  - киоск/клиентский режим (сканирование, просмотр карточки, авто-возврат),
  - менеджерский режим (документы, редактирование, синхронизация, печать, настройки).
- Совместимость с текущим backend API без изменения контрактов (или с опциональным версионированием API).

## 2) Инвентаризация текущих функций (что обязательно перенести)

### 2.1 Клиентский киоск и навигация
- Экран киоска с отдельной логикой входа персонала, полноэкранным режимом, ручным поиском и A4-буфером. 
- Хэш-маршрутизация и восстановление состояния экрана/документа.
- Автофокус невидимого сканер-инпута и перехват сканирования с клавиатурного wedge-сканера.

### 2.2 Поиск товара и карточка
- Поиск товара с цепочкой типов (`barcode`, `char_articul`, `articul`) и отдельной веткой для UID.
- Показ карточки товара, характеристик, галереи изображений, копирования артикула.
- Режим выбора характеристики при множественных характеристиках товара.

### 2.3 Документы и складские операции
- Вкладки документов: приёмка, перемещение, списание, цены.
- CRUD документов и строк, завершение/переоткрытие документов.
- Расчёты остатков и предпросмотр складских строк для операций.
- Валидация ячеек/складов, поддержка известных ячеек и пользовательских правил.

### 2.4 Оффлайн и локальное хранение
- Сохранение документов локально (в вебе: IndexedDB + fallback localStorage).
- Хранение настроек, версии схемы, миграции схемы.
- Outbox-очередь на отправку документов в 1С с ретраями и статусами.
- Локальные логи ошибок и экспорт/шаринг диагностических данных.

### 2.5 Синхронизация и API-интеграция
- Запросы к backend: `/product`, `/update-product`, `/post-document`, `/trigger-sync`, `/stats`, `/warehouses`, `/cells`, `/printers`, `/print-label`, `/print-hanger`, `/print-a4`.
- Поддержка таймаутов, обработка сетевых ошибок, единый формат API-ошибок.
- Ручная синхронизация и фоновые попытки отправки outbox.

### 2.6 Печать
- Печать этикеток (клиентская/складская), хангера, A4-листа (до 10 позиций).
- Режим «сбор A4» в киоске, предпросмотр и удаление позиций из буфера.
- Настройки принтеров и режимов печати (server / PrintNode / custom).
- Редактор ZPL-шаблонов и тестовая печать.

### 2.7 Безопасность и сессии
- Менеджерский пароль + SHA-256 проверка хэша.
- Временная сессия менеджера с TTL и авто-logout.
- Разделение возможностей клиент/менеджер.

### 2.8 PWA-специфика, требующая Android-аналога
- Service Worker-стратегия кэширования (Cache First / Network First).
- Manifest/shortcut/splash-поведение.
- Веб API: Clipboard, Web Share, FileReader, camera input.

## 3) Целевая Android-архитектура (рекомендуемая)

- Язык: **Kotlin** (Java допускается для отдельных модулей/интеграций).
- UI:
  - Вариант A (рекомендуется): **Jetpack Compose** + Navigation.
  - Вариант B (для строгой Java-совместимости): XML + Fragments + Navigation Component.
- Слой данных:
  - **Room** для локальной БД (аналог IndexedDB/localStorage).
  - **DataStore (Preferences)** для настроек и легковесных флагов.
- Сеть:
  - **Retrofit + OkHttp + Moshi/Gson**.
  - Interceptor для `x-api-key`, timeout, логирования, retry-policy.
- Фоновые задачи:
  - **WorkManager** для очереди синхронизации (вместо service worker/ручного таймера в вебе).
- DI:
  - **Hilt/Koin** (или manual DI на старте, если команда избегает DI-фреймворков).
- Слои:
  - `presentation` (UI/ViewModel),
  - `domain` (use-cases),
  - `data` (api, db, mappers, repos).

## 4) Маппинг web-функций на Android-компоненты

### 4.1 Экранная модель
- `screen-kiosk` → `KioskFragment/Screen`.
- `screen-list` (список документов) → `DocsListFragment`.
- `screen-work` (рабочая форма документа) → `DocEditorFragment`.
- Модальные окна web → `DialogFragment`/Compose Dialog.

### 4.2 Сканирование
- Текущий режим ввода через hidden-input и key events:
  - Android: перехват событий от HID/wedge-сканера в Activity/Fragment.
  - Дополнительно: интеграция с **CameraX + ML Kit Barcode Scanning** как fallback для камеры.
- Нормализация кода и триггер поиска — вынести в `ScanUseCase`.

### 4.3 Локальные хранилища
- Документы, outbox, известные ячейки, статус синка:
  - Таблицы Room: `documents`, `document_items`, `outbox`, `sync_status`, `products_cache`, `logs`.
- Настройки (url, apiKey, принтеры, флаги UI, sessionHours): DataStore.
- Миграции схемы: Room Migration + версия конфига DataStore.

### 4.4 Синхронизация
- Ручной sync из UI + периодический background sync:
  - UniqueWork (одиночный),
  - constraints: network connected,
  - backoff exponential.
- Логика отправки outbox и смены статусов (`new/synced/error`) 1:1 с веб-логикой.

### 4.5 Печать
- Путь 1 (приоритетный): печатать через существующий сервер (`/print-*`), чтобы не переносить низкоуровневые протоколы в клиент.
- Путь 2 (опционально):
  - TCP ZPL печать прямо из приложения (сокет на 9100),
  - Android Print Framework для PDF (hanger/A4),
  - Bluetooth SPP для переносимых принтеров.
- Редактор шаблонов ZPL: отдельный экран + предпросмотр текстового шаблона.

### 4.6 Шаринг/экспорт/импорт
- Export JSON: SAF (`ACTION_CREATE_DOCUMENT`).
- Import JSON: SAF (`ACTION_OPEN_DOCUMENT`).
- Share diagnostics: `Intent.ACTION_SEND` (text/file).

## 5) Пошаговый план реализации (без потери функционала)

### Этап 0. Техническая подготовка
1. Зафиксировать API-контракты и форматы payload/response (OpenAPI/Markdown).
2. Составить матрицу parity: web-фича → Android-экран/модуль → критерий готовности.
3. Подготовить набор тестовых данных (товары, характеристики, документы, принтеры).

### Этап 1. Каркас приложения
1. Создать Android-проект (minSdk 23, targetSdk актуальный).
2. Добавить модули: `app`, `core-network`, `core-db`, `feature-kiosk`, `feature-docs`, `feature-settings`, `feature-print`.
3. Реализовать базовую навигацию и shell UI (табы/экранные разделы).

### Этап 2. Данные и настройки
1. Room schema:
   - documents + items,
   - outbox,
   - product cache,
   - logs.
2. DataStore schema для всех настроек из веб-версии.
3. Миграционный импорт (если нужен перенос с web/PWA backup JSON).

### Этап 3. API-слой
1. Реализовать Retrofit интерфейсы для всех существующих endpoint.
2. Централизовать auth headers (`x-api-key`, basic там, где нужно через backend).
3. Унифицировать ошибки (timeout/network/http) в domain-модель.

### Этап 4. Критичный пользовательский поток (MVP parity)
1. Киоск экран + сканирование + ручной поиск.
2. Поиск `/product` по цепочке типов + показ карточки.
3. Вход менеджера, сессия TTL, logout.
4. Список/создание/редактирование документов.
5. Добавление строк в документ и локальное сохранение.

### Этап 5. Синхронизация и outbox
1. Очередь outbox с idempotency-подходом.
2. WorkManager worker: отправка `/post-document`, обработка ошибок, retry.
3. Ручной sync-кнопкой + статус индикаторы в UI.

### Этап 6. Продвинутые складские операции
1. Предпросмотры остатков для списания/перемещения/приёмки/цен.
2. Валидация ячеек, sync `/cells` и `/warehouses`.
3. Выбор характеристики товара и корректная привязка UID/char.

### Этап 7. Печать parity
1. Экран настроек печати + загрузка `/printers`.
2. Печать client/warehouse label, hanger, A4 через backend.
3. Буфер A4 (до 10), сбор из киоска, предпросмотр и очистка.
4. Тестовая печать и детализированные ошибки печати.

### Этап 8. Медиа и UX-паритет
1. Фото товара/приёмки через CameraX + сжатие/обрезка.
2. Галерея в карточке товара.
3. Копирование артикула в буфер и share действий.
4. Экран логов + экспорт в файл.

### Этап 9. Релизная готовность
1. Полный regression checklist по parity-матрице.
2. Нагрузочные и offline-тесты (airplane mode, flaky network).
3. Подготовка release pipeline, подпись APK/AAB, staging rollout.

## 6) Детали совместимости с Android 6 (API 23)

- Runtime permissions:
  - `CAMERA` для сканирования/фото,
  - `WRITE_EXTERNAL_STORAGE`/`READ_EXTERNAL_STORAGE` (ограниченно, где действительно нужно для API 23).
- TLS/сеть:
  - проверить совместимость шифров и сертификатов backend для старых Android.
  - при необходимости включить Network Security Config.
- Фоновые задачи:
  - WorkManager backport поддерживает API 23, но учитывать ограничения Doze.
- Производительность:
  - минимизировать тяжёлые операции на UI потоке,
  - использовать paging/lazy списки для больших документов.

## 7) План тестирования (обязательный минимум)

### 7.1 Unit
- Валидация полей и бизнес-правил (ячейки, метры, состав, цены).
- Mapping API ↔ Domain ↔ DB.
- Алгоритм очереди outbox и retry.

### 7.2 Integration
- Room migration tests.
- Retrofit contract tests (mock server).
- WorkManager tests для фонового sync.

### 7.3 UI/E2E
- Сценарии: kiosk scan → product → manager edit → document post.
- Печать: label/hanger/A4 со всеми ошибочными ветками.
- Offline-first сценарии: создание документов без сети и последующий sync.

### 7.4 Device matrix
- Android 6/7/8/10/12/14, разные DPI/размеры.
- Планшеты + телефоны + устройства с аппаратным сканером.

## 8) Риски и как их закрыть

1. **Сканерная совместимость (разные устройства/wedge).**
   - Решение: абстракция input pipeline + набор device-specific профилей.
2. **Печать (разные принтеры/протоколы).**
   - Решение: сначала печать только через backend `/print-*`, локальные драйверы — второй фазой.
3. **Разночтения бизнес-логики web vs Android.**
   - Решение: parity-матрица + golden test cases на одинаковых данных.
4. **Оффлайн-гонки и дубликаты отправки.**
   - Решение: строгие статусы outbox, дедупликация по docId/operationId.

## 9) Рекомендуемый график (реалистично)

- Sprint 1–2: каркас + данные + login + kiosk + поиск.
- Sprint 3–4: документы + outbox + sync.
- Sprint 5: печать + расширенные операции.
- Sprint 6: стабилизация, тесты, beta.
- Sprint 7: hardening под Android 6 устройства и production rollout.
