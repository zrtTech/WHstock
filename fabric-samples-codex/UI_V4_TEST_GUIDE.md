# UI v4 — как проверить полный макет учёта образцов

**Файл:** `UI_PROTOTYPE_V4.html` — автономный HTML, открыть двойным щелчком в Windows.

**Это не рабочая система:** все товары, полки, остатки, сканы и проверки демонстрационные. Реального подключения к 1С, Chainway C5, USB-сканеру, серверу, печати или базе данных нет. После F5 данные сбрасываются.

## Главное изменение относительно v3

Главная страница больше не привязана к рабочей полке. Она показывает весь склад. Полка появляется крупно только на экранах конкретной операции.

Навигация: **Обзор склада → Все полки → Аналитика → Работа на полке**. В рабочем процессе есть «← Назад», «Обзор склада» и подтверждаемая отмена незавершённой проверки или партии создания.

## Исходные демоданные (после F5)

| Показатель | Ожидается |
|---|---:|
| Товаров в каталоге | 140 |
| Активных физических образцов | 80 |
| Товаров без единого активного образца | 60 |
| Образцов с нулевым остатком товара (демо) | 20 |
| Чужих образцов, обнаруженных при проверке B-01-02 | 50 |
| Не найденных при завершённой проверке B-01-02 | 8 |
| Проверено полок | 1 из 4 |

Список полок: A-02-03, B-01-02, C-01-04, D-03-01. **Только B-01-02** имеет начальную завершённую проверку. У остальных статус **«Не проверялась»**. Прочерк в графах «чужие/не найдены» означает отсутствие данных, а не отсутствие проблем.

## Проверка 1. Главный экран

1. Откройте файл: должен появиться **«Обзор всего склада»**, а не рабочая полка B-01-02.
2. Проверьте все восемь показателей и подпись о демонстрационных данных.
3. Нажмите «Товаров без образца» — откроется соответствующий список аналитики.
4. Нажмите «Обзор склада», затем «Все полки»: должны быть видны четыре полки, включая непроверенные.
5. Нажмите «Работать с полкой» напротив C-01-04: только теперь сверху должна появиться большая рабочая полка C-01-04.

## Проверка 2. Товары без образцов → создание партии

1. «Обзор склада» → «Товаров без образца» → «Выбрать все 60».
2. Нажмите «Добавить выбранные в очередь».
3. Программа **обязана попросить подтвердить полку размещения**. Выберите B-01-02 и подтвердите.
4. Откроется создание партии с 60 товарами в очереди. Проверьте список и количество.
5. Подтвердите создание 60 физических образцов. Каждый должен получить отдельный код.
6. Вернитесь в обзор: активных образцов станет 140, товаров без образца — 0. Никаких реальных записей в 1С не будет.

## Проверка 3. Неправильные места и отсутствующие образцы

1. После F5 откройте «Обзор склада» → «Не на месте»: должно быть 50 строк.
2. В каждой строке должны быть видны код образца, товар, учётная полка и где обнаружен.
3. Нажмите «Открыть полку» у строки: рабочая полка должна соответствовать **фактическому обнаружению**, то есть B-01-02.
4. «Исправить места» → «Выбрать все 50» → «Оставить здесь — исправить учёт» → подтвердите.
5. В общем обзоре «Не на месте» должно стать 0.
6. Отдельно проверьте «Не найдены» — 8 образцов остаются активными; отсутствие не вызывает удаление.

## Проверка 4. Кандидаты на удаление

1. После F5 нажмите «Кандидаты на пересмотр» — 20 образцов с нулевым остатком товара.
2. Ничего не должно удаляться автоматически.
3. «Перейти к ручному отбору на удаление» → выбрать нужные → отдельное подтверждение с галочкой.
4. После подтверждения количество активных образцов уменьшится; история останется в демонстрационном журнале.

## Проверка 5. Проверка полки и сканирование подряд

1. «Все полки» → B-01-02 → «Проверить».
2. «Начать новую проверку».
3. Введите `S-000001`, `S-000002`, `S-000003` подряд. Полные известные коды в демо принимаются автоматически; USB HID с Enter также поддерживается браузерной логикой.
4. Повторите `S-000001`: счётчик уникальных не должен увеличиться.
5. Нажмите «← Назад», вернитесь: незавершённая проверка должна сохраниться.
6. «Отменить проверку» требует подтверждения. Пока проверка незавершена, нельзя незаметно начать новую проверку другой полки с потерей данных.

## Как оценить удобство

Попросите человека с небольшим опытом работы на компьютере без подсказок:
- найти, сколько всего образцов на складе;
- найти товары, у которых вообще нет образца;
- понять, какая полка не проверялась;
- найти 50 образцов не на месте;
- добавить несколько новых образцов;
- понять, что нулевой остаток не означает автоматическое удаление.

Запишите непонятные названия, лишние клики, ошибочные действия и места, где требуется объяснение.

## Что остаётся за пределами макета

- Настоящие остатки 1С и их актуальность; склад/агрегация не проверены.
- Реальное RFID-считывание, USB HID, C5 и офлайн-синхронизация.
- Реальная база, аудит, идемпотентность и права доступа.
- Полноценная история нескольких проверок каждой полки и межскладская аналитика.
- Настоящие рекомендации «убрать/сохранить образец»: правила должны быть согласованы, а не выведены автоматически только по остатку 0.

В реальном приложении Codex обязан проверять эти интеграции и ограничения отдельно. Макет v4 — для согласования сценариев и визуального дизайна.
