# Инструкции Codex

## Принципы
Разрабатывай маленькую, проверяемую систему для ежедневной работы кладовщика. Приоритет: минимум кликов, отсутствие повторного сканирования, сохранность данных и простота поддержки.

## Неизменяемые бизнес-правила
1. У образца ровно три учётных действия: СОЗДАТЬ, ПЕРЕМЕСТИТЬ, УДАЛИТЬ НАВСЕГДА.
2. Сканирование, поиск, обнаружение на другой полке и проверка мест — наблюдения, не перемещения.
3. Нельзя автоматически переносить образец по результату RFID/ШК-сканирования.
4. Отсутствие при обходе не означает удаления.
5. Удалённый образец не восстанавливается; его история сохраняется как tombstone.
6. При неоднозначном товарном ШК нельзя угадывать конкретный экземпляр образца.
7. Каждое изменение состояния и соответствующее событие фиксируются в ОДНОЙ транзакции.
8. Повтор одного requestId с тем же телом возвращает тот же результат; с другим телом — конфликт.
9. Исторические привязки EPC не переписываются при повторном использовании RFID-метки.
10. Не писать SQL напрямую в базу 1С и не создавать документы 1С в фоне.

## Код и структура
- Python с типами, форматирование Ruff, pytest, Alembic, SQLAlchemy 2.x.
- Backend — единственный владелец операций и проверок, desktop/C5 — клиенты.
- Разделить domain, persistence, API, 1c_adapter, desktop, device_adapter.
- DTO/схемы API версионировать (/api/v1). Даты UTC в ISO 8601.
- Публичные ошибки структурировать: code, message, details, requestId.
- Не хранить пароль в исходниках, логах, коммитах или примерах конфигурации.
- Не отключать TLS и проверку сертификатов ради прохождения теста.
- Любой сетевой запрос ограничивать таймаутом; синхронизацию 1С выполнять отдельно от действий оператора.
- Каждое изменение схемы оформлять миграцией и обратимым/безопасным планом обновления.

## Обязательные тесты на каждую операцию
- Успех, повтор requestId, изменение payload при том же requestId.
- Одновременные запросы, устаревшая версия образца.
- Удалённый объект, неверное место, неизвестный код.
- Отказ БД между записью состояния и событием — ни одно не должно остаться отдельно.
- Проверка, что наблюдение не меняет текущее место.

## Интерфейс
- После чтения ШК/ EPC контекст образца сохраняется на экране до завершения действия.
- Не требовать повторного поиска или сканирования для перемещения/удаления.
- Фокус сканирования восстанавливается после успешного действия.
- Для опасного удаления нужно подтверждение, но не длинная форма.

## Работа по этапам
На каждом этапе: код + миграция (если нужна) + автоматические тесты + краткий CHANGELOG + инструкции запуска. Не реализовывать фиктивные интеграции с 1С/C5 как настоящие. Если внешний контракт неизвестен, оставить адаптер и пометить блокировку интеграции.

## Готовность
Не писать «готово», если не выполнены критерии ACCEPTANCE.md на настоящем Windows и с реальным сканером. Все решения, отличающиеся от DECISIONS.md, фиксировать в ADR.
