# Поэтапный план для Codex

Каждый этап заканчивается: код + тесты + команда запуска + краткий отчёт. Нельзя объявлять этап выполненным, если его критерии не пройдены.

## Этап 0. Аудит среды
Проверить Python/.NET, Windows, SQL Server 2022, доступ 1С read-only, USB-сканер, C5, сеть, принтер, существующее расширение УОТ_* и исходники APK. Не менять систему. Результат ENVIRONMENT_AUDIT.md.

## Этап 1. Каркас и модель
Создать backend/, desktop/, tests/, migrations/. Создать виртуальное окружение, зависимости, Ruff, pytest, CI-скрипт. Поднять тестовый FastAPI и SQL Server БД, оформить 001_schema.sql как миграцию. Результат: локально запускаемый backend, миграции up/down, тест соединения.

## Этап 2. Домен
Реализовать CREATE, MOVE, DELETE, ID генерацию, optimistic concurrency, транзакционные SampleEvents, IdempotencyRequests, TagAssignments. Тесты всех инвариантов. Результат: тестируемые сервисы без UI.

## Этап 3. API
Реализовать API_CONTRACTS.md, аутентификацию, роли, ошибки, идемпотентность, OpenAPI. Интеграционные тесты на SQL Server.

## Этап 4. Каталог 1С
Адаптер OData/HTTP по реальному $metadata, read-only sync и кэш. Протокол сравнения с 1С на 20 тестовых товарах, включая пустой основной ШК.

## Этап 5. Windows UI
PySide6: поиск, контекст места, создание, перемещение одним нажатием, удаление с подтверждением, история, проверки. Подключить USB HID сканер. UI tests и реальное сканирование.

## Этап 6. Проверки мест
Snapshot ожидаемых образцов, наблюдения EPC, категории found/missing/unexpected/unknown. Никаких автоматических MOVE/DELETE. Тест изменения учётного места параллельно проверке.

## Этап 7. Chainway C5
Проверить SDK, текущий APK, способ установки и сеть. При возможности использовать существующий клиент, иначе создать Android клиент. Подключить RFID/2D, очередь offline, повтор запросов, конфликты. Испытать физически.

## Этап 8. Packaging
Собрать Windows .exe и службу, установщик, конфигурацию, журнал, резервное копирование. Установить на тестовую машину, проверить reboot.

## Этап 9. Приёмка
Выполнить ACCEPTANCE.md и TEST_PLAN.md на реальном ПК/C5/сканере. Не отмечать hardware-тесты PASS, если устройство недоступно.

## Этап 10. Перенос существующих образцов (если нужно)
Только после аудита старого расширения и согласования; выгрузка read-only, тестовый импорт, сверка sampleCode/EPC/мест и количества, backup, безопасный переход.


## Обязательный этап: массовые сценарии UI и API

До завершения Windows UI:
- Реализовать очередь 100 последовательных сканирований на одну выбранную полку, без модального окна на каждый скан.
- Реализовать пакетный CREATE одной транзакцией с одним batchRequestId, 100 sampleCode и 100 событиями.
- Реализовать рабочий список 50+ строк с фильтрами по полке, статусу, обнаружению и остаткам 1С, выделением всех строк фильтра.
- Реализовать предпросмотр и атомарный пакетный MOVE/DELETE, включая конфликты версий.
- Проверить отдельные поля workingLocationId, accountedLocationId, observedLocationId, targetLocationId.
- Выполнить сценарии A–I из BULK_UX_SPEC.md.
- Ориентироваться на UI_PROTOTYPE_V2.html, а не на старый UI_PROTOTYPE.html.
