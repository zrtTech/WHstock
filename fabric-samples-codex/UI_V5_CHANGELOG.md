# Исправление массовых действий — макет v5

**Открыть:** `UI_PROTOTYPE_V5.html`. Автономный HTML, без подключений и сохранения после F5.

## Почему v4 был неудобен

После выбора образцов появлялась кнопка «Посмотреть выбранные». Для списка «Не найдены» она не приводила к рабочему действию, а показывала предупреждение. Это тупик, а не сценарий оператора.

## Исправлено

В списке «Исправить места» кнопка теперь называется **«Выбрать действие для N образцов»**. Следующий экран показывает разные действия в зависимости от проблемы.

**Чужие на полке:** закрепить за текущей полкой, получить памятку о физическом разносе, переместить на другую полку.

**Не найдены:** отметить для поиска (остаются активными, не меняется полка), подтвердить фактическое обнаружение на учётной полке (наблюдение, не перемещение), подтвердить физическое обнаружение на другой полке и изменить учётное место, либо отдельно исключить из активного учёта с подтверждением.

Для подтверждения физического обнаружения обязательно отметить галочку, что все выбранные образцы найдены. Для другой полки нужно выбрать её явно. Нельзя автоматически удалить образцы только потому, что их не нашли при проверке.

## Быстрые тесты

1. Откройте v5 → «Работа на полке» → B-01-02 → «Исправить места» → «Не найдены: 8».
2. Нажмите «Выбрать все 8» → «Выбрать действие для 8 образцов».
3. «Оставить в списке поиска» → «Проверить действие» → подтвердить. Восемь образцов остаются активными и числятся на тех же полках; в списке появляется пометка «В поиске».
4. Повторите выбор восьми → «Нашёл на учётной полке». Без подтверждения фактического обнаружения продолжить нельзя. После подтверждения число неразрешённых «Не найдены» станет 0, учётные места не изменятся.
5. Обновите страницу F5 и повторите с «Нашёл на другой полке»: выберите другую полку и подтвердите физическое обнаружение всех восьми. После выполнения их учётные места изменятся.
6. После F5 повторите с «Убрать из активного учёта». Без отдельной галочки подтверждения удаление заблокировано.

## Ограничение

Это только демонстрационная логика. Список «В поиске» хранится в памяти страницы; для настоящего приложения потребуется отдельная учётная запись решения, аудита и роли, а также механизм контроля фактического обнаружения. Снимок завершённой проверки остаётся историческим; в макете количество «Не найдены» трактуется как **неразрешённые проблемы**, а не исходное число пропусков в отчёте проверки.
