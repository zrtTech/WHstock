# UX v2: массовое создание и массовая обработка образцов

Дата: 2026-10-29. **Приоритет:** этот документ заменяет одиночный workflow создания и основной экран «одна карточка» из UX_FLOWS.md и UI_PROTOTYPE.html. Старый макет не принимать как дизайн для production.

## 1. Ключевой рабочий принцип

Главный объект интерфейса — **полка и список физических образцов**, а не карточка одного образца. Основные режимы Windows UI:

- **Рабочий список:** компактная таблица с фильтрами, множественным выбором, массовыми действиями и быстрым переходом к индивидуальному действию.
- **Создать партией:** одна полка + поток сканирования 100 и более товарных ШК + очередь + одно сохранение партии.
- **Проверка полки:** зафиксированный снимок ожидаемых экземпляров + наблюдения + передача проблемных строк в рабочий список.
- **История:** аудит операций; не пользовательский архив удалённых образцов.

## 2. Создание 100 образцов

1. Оператор выбирает/сканирует **полку назначения** ОДИН раз.
2. Сканирует 100 товарных штрихкодов подряд. После каждого Enter приложение автоматически добавляет одну единицу в очередь, возвращает фокус сканеру и подаёт короткий визуальный сигнал.
3. Таблица очереди показывает товар, артикул, код, количество образцов по товару, повторы, неизвестные коды, общую сумму экземпляров и полку партии.
4. **Один скан = один физический экземпляр**; повтор одного товара увеличивает количество и выделяется как повтор. Пользователь может исправить количество кнопками +/-; это защищает от случайного двойного скана, не запрещая два реальных образца одного товара.
5. Нераспознанные/неоднозначные товарные коды видны как ошибки. Сохранение партии запрещено до их разрешения.
6. Кнопка «Создать N образцов на полке X» сохраняет N отдельных Sample с уникальными sampleCode и одинаковым locationId.
7. Результат: сводка N создано, 0/количество ошибок, список созданных кодов, возможность печати этикеток (после проверки принтера), переход в рабочий список этой полки.
8. Не создавать образцы по мере сканирования. **До подтверждения партия только в очереди**. Потеря фокуса или повторный Enter не должны создавать лишние строки без нового события сканирования.
9. При смене полки с непустой очередью — явное предупреждение: «Все N образцов будут созданы на новой полке»; не смешивать назначения без явного решения.
10. При обрыве соединения во время сохранения нельзя повторно создать партию. Нужен постоянный batchRequestId, детерминированные itemRequestId и возврат уже сохранённого результата.

## 3. Массовые исправления (50+ образцов)

Основной экран — таблица со строками высотой ~36–44 px, прокруткой и закреплённым заголовком. Поля:

| Выбор | Код образца | Товар / артикул | Учётная полка | Обнаружен на | Статус проверки | Остаток 1С | Действие |
|---|---|---|---|---|---|---|---|

Сверху: **рабочая полка** (контекст проверки), источник списка (обнаружены здесь / числятся здесь / все связанные), статус (чужие / не найдены / на месте / все), остаток 1С (0 / любой), поиск по коду/артикулу/EPC. Счётчики: всего, не на месте, не найдены, нулевой остаток, выбрано.

Снизу: явная **целевая полка** (отдельная от рабочей) и действия:
- «Переместить выбранные на целевую полку».
- «Переместить по факту обнаружения» — если у выбранных есть подтверждённые наблюдения и разные целевые полки; предпросмотр построчно.
- «Удалить выбранные» — подтверждение количества, кодов и необратимости.

Массовые действия — явные команды пользователя; сканирование и проверка сами ничего не перемещают и не удаляют. Выбор всех относится к **отфильтрованному набору**, а не только к видимым 10 строкам. Предпросмотр должен показывать фактические целевые места и потенциальные конфликты. При изменении версии записи между выбором и подтверждением сервер возвращает конфликт по конкретной строке; остальные результаты прозрачно отображаются.

## 4. Полки: нельзя путать

- **Рабочая полка** — место, которое сейчас проверяем, где физически нашли образцы.
- **Учётная полка** — место, закреплённое за конкретным образцом в системе.
- **Целевая полка** — место, на которое оператор намеренно перемещает выбранные образцы.
- **Обнаружен на** — место из наблюдения с временем, источником (C5/Windows) и идентификатором проверки; не является автоматическим изменением учёта.

При «чужом» образце учётная и обнаруженная полки отличаются. При «не найден» отсутствие должно относиться к **завершённой проверке** с замороженным snapshot; если проверки не было, статус «не проверялся», а не «отсутствует».

## 5. Остатки 1С

Фильтр «Остаток 1С = 0» помогает найти кандидатов на ручное удаление образцов, но:
- нулевой остаток ткани **не означает**, что образец физически исчез;
- устаревшие данные 1С нельзя представлять как актуальные;
- в UI показывать время последней синхронизации и склад/агрегацию;
- не удалять автоматически, не помечать образец удалённым без подтверждения.

## 6. Производительность и клавиатура

- Обрабатывать 100 сканирований без открытия диалогов на каждое.
- Сохранять фокус сканирования, поддерживать HID Enter.
- Таблица рассчитана на сотни строк: фильтры, выбор всех, виртуализация при больших объёмах.
- У пользователя виден прогресс партии, ошибки, результат и число успешно обработанных.
- Для ручного удаления одного образца — выбрать строку и нажать удалить, подтвердить; без повторного сканирования.

## 7. Приёмочные сценарии

A. Выбрать B-01-02, отсканировать 100 различных товарных ШК, увидеть 100 строк, нажать «Создать 100» — ровно 100 уникальных образцов на B-01-02, без документов 1С.
B. Сканировать один ШК дважды — количество 2 с предупреждением, после сохранения два разных sampleCode.
C. В очереди неизвестный ШК — сохранить нельзя; можно удалить/исправить строку.
D. На B-01-02 обнаружены 50 образцов, учётные места A/C. В рабочем списке видны 50 строк и обе полки; «Выбрать все» → «Переместить на B-01-02» → предпросмотр → ровно 50 MOVE событий, ни одного нового сканирования.
E. Из фильтра «Остаток 1С = 0» отметить 20 образцов → «Удалить выбранные» → подтверждение → 20 tombstones, журнал событий сохранён, 1С без изменений.
F. После проверки 8 не найденных образцов остаются активными, пока пользователь не решит отдельно.
G. В одном списке несколько фактических полок → «Переместить по факту обнаружения» с построчным предпросмотром.
H. Обрыв Wi-Fi/HTTP после commit пакетного создания → повтор того же batchRequestId возвращает тот же набор 100 кодов, не создаёт ещё 100.
I. Конкурирующие массовые операции с устаревшими версиями → сервер возвращает конфликты и список реально применённых изменений; UI не скрывает частичные результаты.
