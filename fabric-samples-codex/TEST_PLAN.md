# План испытаний

## Unit
- CREATE образца с/без EPC.
- MOVE в новое/то же место.
- DELETE и повтор DELETE.
- MOVE удалённого экземпляра.
- Один товар с 0/1/N образцами.
- Товарный ШК с 2 образцами возвращает MULTIPLE, а не первый.
- EPC уже активен у другого образца => 409.
- Повтор одного requestId с одинаковым payload => один Event.
- Повтор requestId с другим payload => 409.
- expectedVersion устарел => 409.
- Неизвестный ШК/EPC и неактивное место.
- Редактирование/удаление Event невозможно из прикладного API.

## Integration
- Транзакция CREATE/MOVE/DELETE + Event + RequestLog: атомарность при ошибке записи.
- Две одновременные команды MOVE одного образца.
- Два одновременных CREATE с одним requestId.
- Два параллельных назначения одного EPC.
- Замена EPC закрывает старый интервал и не меняет историю.
- Старт проверки фиксирует snapshot; MOVE во время проверки не меняет ожидаемый список.
- Сканирование чужого EPC не изменяет location_id.
- Ненайденный образец не удаляется.
- Ошибки 1С: timeout, 401, 500, недоступность, частичная пагинация.
- Восстановление SQL backup в отдельную БД, сверка событий.

## Hardware/E2E
- USB-HID сканер: быстрый поток, Enter, кириллическая раскладка, фокус.
- Chainway C5: реальное чтение UHF и 2D, соседние стойки, несколько меток в поле, дедупликация.
- Отключить Wi-Fi до и после серверного commit; очередь повторяется без дублей.
- Закрыть Windows UI: API продолжает работать для C5.
- Перезагрузить Windows: служба поднимается, данные сохранены.
- 10 000 товаров, 100 000 событий — замер времени поиска/записи и размера БД.
