# Учёт образцов тканей — комплект для Codex

Версия спецификации: 2026-10-29. Язык продукта и интерфейса: русский.

## Цель
Создать отдельное приложение для Windows, учитывающее физические образцы тканей и их местоположение. Справочник товаров и при необходимости остатки считываются из 1С:УНФ; движения образцов хранятся только в собственной базе приложения. Никаких документов 1С для операций с образцами.

## Подтверждённая среда
- Windows; Microsoft SQL Server 2022.
- 1С:УНФ 3.0.14.123, платформа 8.5.1.1343; веб-публикация через Apache.
- Терминал Chainway C5, Android, RFID UHF и 2D.
- Около 10 000 товарных позиций; количество физических образцов не равно количеству товаров.
- Стационарный сканер ШК должен работать с Windows-программой.

## Рабочее техническое решение
- Windows UI: Python 3.12+, PySide6 (нативное окно, не браузер).
- Сервер/API: Python, FastAPI; отдельный процесс/Windows Service на компьютере в локальной сети.
- БД: отдельная база Microsoft SQL Server, не схема базы 1С; SQLAlchemy + pyodbc + Alembic.
- Связь с 1С: только чтение через проверенный OData/HTTP-интерфейс либо регламентированный экспорт.
- Chainway C5: Android-клиент обращается к API по локальной сети; совместимость имеющегося APK/SDK нужно проверить.
- Тесты: pytest; развёртывание Windows: установщик/сервис после проверки прототипа.

Это рабочий выбор для старта, а не доказательство совместимости с существующим APK C5.

## Первая задача для Codex
Прочитай весь комплект. Создай структуру проекта с папками backend/, desktop/, tests/, migrations/, scripts/, docs/. Реализуй этап 1 из TASKS.md: запускаемый FastAPI, миграции, тестовая БД, справочник мест, создание/перемещение/удаление образцов, неизменяемый журнал событий и идемпотентность. 1С и C5 пока заменить тестовыми адаптерами. Не объявляй готовность до выполнения ACCEPTANCE.md.

## Что НЕ содержится в комплекте
Это исходные требования и стартовая SQL-схема, а не готовое приложение. Здесь нет паролей, адресов сервера, секретов 1С, исходников APK C5 или подтверждённой схемы OData конкретной публикации. Codex должен получить эти данные на этапе интеграции, а не выдумывать их.
