# Как проверить новый интерфейс v3

**Это интерактивный макет для оператора, а не готовое приложение.** В нём вымышленные товары, полки и образцы. 1С, сканер, C5 и сервер не подключены. После F5 все изменения исчезают.

## Как открыть

1. Откройте UI_PROTOTYPE_V3.html на GitHub.
2. Нажмите **Download raw file** (скачать исходный файл).
3. Дважды щёлкните по скачанному файлу в Windows: он откроется в браузере.
4. Для проверки удобно использовать окно браузера на весь экран.

## Тест 1. Оператор должен сразу понять, где работает

- На главном экране крупно написано **B-01-02**.
- Есть четыре больших действия: **Добавить образцы**, **Проверить полку**, **Исправить места**, **Убрать образцы**.
- Нажмите **Сменить полку**, выберите другую, подтвердите. На каждом рабочем экране новая полка должна быть крупно видна.
- Верните B-01-02 для следующих тестов.

## Тест 2. Создать 100 образцов

1. Откройте **Добавить образцы**.
2. Введите товарный код `4600000000001` и нажмите Enter; поле снова должно быть готово к сканированию.
3. Введите этот код ещё раз: в очереди должно быть **2 образца** одного товара, с заметным повтором.
4. Введите `UNKNOWN`: сохранение должно блокироваться, пока ошибочная строка не удалена.
5. Для быстрого теста нажмите **Загрузить пример: 100 товаров**.
6. Нажмите **Проверить и создать 100**.
7. Проверьте большую надпись с количеством и полкой, затем подтвердите.
8. На экране результата должны быть **100 уникальных кодов образцов** и надпись о создании 100 из 100.

**Важно:** макет не создаёт реальных образцов, не печатает этикетки и не записывает данные в 1С.

## Тест 3. Проверить полку

1. Вернитесь на главную страницу, убедитесь, что выбрана B-01-02.
2. Откройте **Проверить полку** и нажмите **Начать новую проверку**.
3. Нажмите **Загрузить демо: 50 чужих + 8 отсутствующих**.
4. Пока проверка идёт, образцы не должны считаться удалёнными или перемещёнными.
5. Нажмите **Завершить проверку**.
6. Ожидаемый результат для исходных демонстрационных данных: **50 чужих**, **8 не найденных**, **12 на месте**.

Если до теста вы уже переместили или удалили образцы, цифры будут другими. Для чистого теста нажмите F5.

## Тест 4. Исправить 50 неправильных мест

1. На исходных данных откройте **Исправить места**.
2. Должно быть видно **50 чужих образцов**.
3. Нажмите **Выбрать все 50**: надпись должна стать **«Выбрано 50 из 50»**.
4. Нажмите **Продолжить: выбрать действие**.
5. Выберите **Оставить на полке B-01-02 — исправить учёт**.
6. Проверьте предпросмотр и подтвердите.
7. Результат — **50 исправленных мест**; на следующем просмотре чужих образцов должно стать 0.

Проверьте отдельно вариант **Физически разнести по учётным полкам**: он должен показывать направления, но **не менять учёт**. Вариант **Переместить на другую полку** требует явного выбора назначения.

## Тест 5. Убрать 20 образцов

1. Нажмите F5, чтобы вернуть исходные демонстрационные данные.
2. Откройте **Убрать образцы**.
3. В фильтре «Товары с нулевым остатком» должно быть **20 образцов** (по всем активным образцам, а не только по выбранной полке).
4. Нажмите **Выбрать все 20**, затем **Продолжить к удалению**.
5. Прочитайте предупреждение. Пока не поставлена отдельная галочка подтверждения, удалить нельзя.
6. Подтвердите удаление: результат — 20 исключённых из активного учёта, запись в демонстрационной истории.

**Нулевой остаток не вызывает удаление автоматически.**

## Тест 6. Ошибки и безопасность

- На экране предпросмотра массового перемещения или удаления нажмите **Имитировать конфликт версии**, затем подтвердите. Результат должен быть: **0 изменений**, весь пакет отклонён.
- Нажмите F5, повторите сценарий и выберите **Имитировать обрыв связи**. Результат должен быть **«Результат неизвестен»**, а не ложное «успешно».
- Проверьте, что кнопки «Назад» и «Главный экран» понятны.
- Проверьте масштаб браузера 125% и 150%, а также экран 1366×768.

## Что оценить самому

Попросите человека, который плохо владеет компьютером, без подсказок:
1. Выбрать полку B-01-02.
2. Добавить пять образцов.
3. Найти и исправить три чужих образца.
4. Убрать два выбранных образца.

Запишите: где остановился, какую кнопку не понял, что сделал не так и сколько подсказок потребовалось. Эти наблюдения важнее внешней красоты.

## Известные ограничения прототипа

- HTML работает в браузере, а итоговое приложение должно быть нативным Windows.
- Демонстрация не проверяет реальные устройства, скорость RFID, 1С, права доступа и сеть.
- Списки и результаты не сохраняются после обновления.
- «Имитировать обрыв связи» — только визуальная проверка поведения, не настоящая офлайн-очередь.
- Печать этикеток не реализована до проверки принтера.
- Реальная реализация должна соблюдать API, атомарные транзакции, идемпотентность и неизменяемый аудит из основного пакета требований.
