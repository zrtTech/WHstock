# Макет v7 — учёт физических образцов тканей

**Открыть макет:** `UI_PROTOTYPE_V7.html`  
**Автотесты:** `UI_PROTOTYPE_V7.test.cjs`

Это интерактивный UX-макет для согласования поведения будущей нативной программы Windows. Данные вымышленные и сохраняются в `localStorage` браузера. Реальных подключений к 1С:УНФ, Chainway C5, RFID SDK, API и базе данных нет. Команды записи EPC и контрольного чтения **имитируются**, физическая метка не программируется.

## Как открыть

1. Скачайте `UI_PROTOTYPE_V7.html` из GitHub (Raw / Download).
2. Откройте файл в Microsoft Edge или Chrome на Windows. Сервер и установка не требуются.
3. При необходимости нажмите «Настройки макета → Сбросить демоданные». **v7 использует отдельное хранилище и схему 7**, не импортируйте резервные копии v6 как v7.
4. Исходные данные: 140 товаров, 80 физических экземпляров, четыре полки. На B-01-02 есть законченная проверка с 50 чужими и 8 не найденными. Через настройки можно создать каталог из 10 000 товаров для теста отчётов.

## Принятые решения

### 1. Отбор образцов на исключение по остатку в 1С

- Оператор **сам задаёт порог в метрах**, например «остаток строго меньше 1 м» или «меньше 0,5 м». Значение сохраняется.
- Система показывает **активные физические экземпляры** товаров, у которых остаток удовлетворяет условию. Один товар может иметь несколько экземпляров; кандидаты перечисляются поэкземплярно.
- Список листается по 50 строк; есть ручной выбор видимых экземпляров, сканирование уникального кода/EPC и просмотр выбранного.
- **Никакой автоматической чистки**. Изменение порога, открытие отчёта и выделение кандидатов ничего не исключают. Оператор физически убирает образцы, затем подтверждает конкретный список на отдельном экране.
- Исключение необратимо в пользовательском интерфейсе. История и tombstone остаются. Данные в 1С никогда не изменяются.
- Остатки в макете вымышленные. В рабочей версии получать их из 1С:УНФ **только на чтение**, показывать дату обновления и проверять единицу измерения/пересчёт в метры. При реальном исключении требуется повторная проверка актуальности данных и версии образца.

**Пример:** «Работа на полке → Убрать образцы → Остаток меньше, метров: 1 → Применить порог → Выбрать нужные → Проверить и подтвердить → Подтвердить физическое исключение». Можно перейти и через «Склад → Кандидатов к исключению» или «Отчёты → Кандидаты».

### 2. Запись RFID-меток, а не только чтение

Отдельная вкладка **«Запись RFID»** и кнопка на экране «Работа на полке».

1. Сканировать товарный ШК или уникальный код физического экземпляра.
2. Если товарному ШК соответствует несколько экземпляров, **выбрать конкретный образец**. Нельзя привязать EPC наугад только по товарному ШК.
3. Нажать «Записать EPC на метку». В макете формируется уникальный демонстрационный EPC и создаётся **незавершённая попытка**; привязка в учёте ещё не меняется.
4. Считать EPC с метки повторно. Только совпадение, уникальность EPC среди активных образцов и совпадение версии позволяют сохранить связь.
5. При перезаписи закрыть старый интервал EPC, открыть новый и записать аудит. При ошибке чтения привязку не создавать. Повторная запись использует тот же EPC; незавершённая попытка переживает обновление страницы. Для отмены требуется отдельное подтверждение с предупреждением о физически уже записанной метке.

**Важно:** кнопка «Демо: считать ожидаемый EPC» не обращается к устройству. Реальная запись, блокировка/разблокировка метки, чтение обратно, подтверждение результата на Chainway C5 и офлайн-синхронизация — обязательные задачи реализации и испытаний на устройстве. Макет не доказывает их работоспособность.

**Без печати:** ни принтер, ни печать наклеек, ни экран «Маркировка» не нужны. Вновь созданные образцы выбираются из списка внутренних уникальных экземпляров; физическая идентификация завершается привязкой EPC. Для нескольких экземпляров одного товара оператор работает с конкретным физическим образцом по одному.

### 3. Исправление образцов, обнаруженных не на своей полке

- В списке «Чужие» основное действие — **«Вернул на [учётная полка]»**. Сначала оператор **физически возвращает** образец, затем фиксирует действие. Простого «Закрепить здесь» без физического исправления больше нет.
- Массовый возврат требует отдельного подтверждения фактического действия.
- Если не найденный образец обнаружен на другой полке, оператор указывает, где его нашёл, **возвращает на учётную полку** и подтверждает. Место в учёте при таком возврате не меняется; сохраняется событие обнаружения.
- Для **настоящего планового перемещения** существует отдельная операция «Переместить», которая изменяет учётную полку после явного действия.
- Исторические снимки проверок остаются неизменными; решения записываются отдельно. Отсутствие образца не означает исключение.

### 4. Права доступа

Отдельной роли администратора **нет**. Макет показывает обычный операторский сценарий. В промышленном приложении нужны идентификация оператора и аудит критических действий, но не отдельное административное разрешение на исключение или изменение данных.

## Проверка полки и постоянная навигация

Главное меню всегда состоит из шести вкладок: **Склад, Работа на полке, Запись RFID, Поиск, Отчёты, Журнал**. Кнопка «Настройки макета» находится отдельно.

Постоянная панель показывает текущую рабочую полку и активную проверку. «К проверке» возвращает к незавершённому сеансу. Проверка остаётся пошаговой:

1. Выбор полки и начало проверки с замораживанием ожидаемого списка.
2. Сканирование USB-HID с Enter или C5. C5-состояние и офлайн-очередь открываются **внутри экрана проверки**.
3. Отдельный экран итогов после явного завершения.
4. Разбор чужих и не найденных с физическим исправлением, не переписывающий историю.

Не завершать проверку при уходе с экрана. Не менять учётное место от одного сканирования. Не скрывать доступ к незавершённой проверке. Неразобранные сканы и неотправленная очередь C5 блокируют завершение.

## Что проверить вручную в браузере

1. **Порог:** «Убрать образцы» → установите 1 м, затем 0,5 м. Количество кандидатов изменится. Выберите несколько: активные образцы останутся до финального подтверждения. При пороге 100 м проверьте переход на вторую страницу.
2. **Исключение:** выберите S-000051 вручную → подтверждение → исключение. Найдите его по коду: tombstone и журнал должны сохраниться.
3. **RFID:** «Запись RFID» → выберите S-000001 → «Записать EPC» → в поле контрольного чтения введите неверный код: привязки нет. Нажмите «Демо: считать ожидаемый EPC»: привязка появляется, старый интервал закрывается.
4. **Неоднозначный ШК:** создайте две физические копии товара ART-0001; сканируйте его товарный ШК в режиме RFID. Программа должна потребовать выбора конкретного экземпляра.
5. **Чужие:** B-01-02 → «Разобрать чужие» → «Вернул на A-02-03» для S-000001. Открытых чужих станет 49, учётная полка останется A-02-03, в старом сеансе останется 50 исторических наблюдений.
6. **Массовый возврат:** выделите оставшихся чужих, нажмите «Вернул ... на свои полки» и подтвердите. Никакой команды «Закрепить здесь» быть не должно.
7. **C5:** начните проверку A-02-03, откройте состояние C5 внутри неё, имитируйте офлайн-скан, верните сеть и отправьте очередь.
8. **Печать:** в интерфейсе нет кнопок печати и нет режима создания наклеек.

## Автоматические тесты

В каталоге с двумя файлами:

```powershell
node .\UI_PROTOTYPE_V7.test.cjs
```

Набор содержит **33 теста**: пороги и пагинация, ручное исключение, физический возврат, создание, RFID-запись/чтение/ошибки/история EPC, идемпотентность, снимки проверок, офлайн C5, навигация и отчёты. Тесты не используют npm.

## Задание для Codex на Windows

Реализовать и **запустить на вашем Windows-компьютере** нативную программу по этому UX-образцу, с отдельным фоновым API и БД, аудитом и проверками конфликтов/идемпотентности. Подключить 1С:УНФ исключительно на чтение, проверить реальные остатки и единицы измерения, реализовать на Chainway C5 запись UHF EPC с контрольным чтением, обеспечить сохранность незавершённых операций и офлайн-очереди. Протестировать USB-HID сканер, C5 и производительность на 10 000 товаров. **Принтер и административную роль не реализовывать.**

Этот HTML — интерактивный макет, **не** готовая производственная Windows-программа. Визуальное отображение на конкретном мониторе и реальное оборудование здесь не испытаны.
