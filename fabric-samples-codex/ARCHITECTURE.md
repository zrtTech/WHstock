# Архитектура

## Компоненты
1. Desktop Windows (Python/PySide6): ввод HID-ШК, интерфейс, поиск, создание, перемещение, удаление, проверки. Никакой прямой записи в БД.
2. Backend (FastAPI): аутентификация, доменные правила, API, транзакции, идемпотентность, журнал событий.
3. Microsoft SQL Server: отдельная БД FabricSamples, отдельный логин с минимальными правами. Никаких таблиц 1С.
4. Адаптер 1С: чтение товаров, ШК и при подтверждении API — агрегированных остатков; синхронизация в кэш, без блокировки работы при кратком отказе 1С.
5. Android Chainway C5: клиент по HTTPS в LAN, локальная очередь при потере связи, аппаратный RFID SDK/сканер в Android-клиенте.
6. Фоновый синхронизатор: плановое чтение 1С, метрики и протокол ошибок.

## Поток
1С:УНФ --(read-only OData/HTTP/export)--> 1c_adapter --> ProductCache в отдельной SQL Server БД.
Windows PySide6 --(HTTPS JSON)--> FastAPI --(transaction)--> FabricSamples DB.
Chainway C5 --(HTTPS JSON)--> тот же FastAPI.

## Процессы и развёртывание
- Сервер FastAPI работает как Windows Service под отдельной учётной записью.
- Desktop — обычный Windows .exe, подключается к серверу по конфигурации.
- Для одного ПК сервер и desktop могут жить на одной машине, но API остаётся обязательным ради C5 и нескольких рабочих мест.
- БД размещается на существующем SQL Server 2022 при наличии разрешений/ресурсов.
- Миграции выполняются отдельной командой при обновлении, не при каждом старте UI.

## Слои backend
api/ -> application/ -> domain/ -> persistence/. Адаптеры 1С и устройств отделены интерфейсами. Внутри домена нет импортов PySide6, SQLAlchemy моделей или 1С.

## Конкурентность
При изменении образца проверять ожидаемую версию, блокировать строку транзакцией и менять её вместе с записью Event и Idempotency. SQL Server isolation: READ COMMITTED с явной блокировкой строки либо SERIALIZABLE там, где проверяются уникальность/перекрытия EPC. Для сохранения ответов повторов хранить результат запроса в той же транзакции.

## Надёжность
- C5: локальная долговременная очередь с requestId; повтор в порядке операций одного образца; конфликт требует решения оператора, не автоперезапись.
- Проверки: snapshot на момент начала, не динамический запрос текущего места.
- Часы: серверные UTC timestamps; клиентское время — только диагностический атрибут.
- В 1С интеграции: ограниченные права на чтение, таймауты, backoff, мониторинг последнего успешного sync.

## Безопасность
HTTPS для C5/LAN; учётные записи/токены устройств; роли Operator/Admin; журнал автора; запрет хранения секретов в Git. Операции удаления требуют права и подтверждения UI. Токены не передавать в query string.

## Вне границ
1С остаётся источником товарных данных и складских остатков. Это приложение — единственный источник истины о местонахождении физических образцов. Состояния не синхронизируются обратно в 1С, пока не принято отдельное решение.
