# Образцы тканей — интерактивный макет v10

**[Открыть HTML-макет v10](UI_PROTOTYPE_V10.html)**

## Как запустить

Скачайте файл **UI_PROTOTYPE_V10.html** и откройте его двойным щелчком в Microsoft Edge или Google Chrome на Windows. Для демонстрации не нужен сервер, npm, 1С или Chainway C5. Данные демомакета хранятся только в localStorage текущего браузера (ключ `fabric-prototype-v10`). Данные v9 не изменяются. Для начала с чистого состояния откройте «Система» → «Сбросить демомакет».

## Что изменено по сравнению с v9

- Постоянная навигация: **Склад, Операции, Артикулы, Отбор по остаткам, Отчёты, Журнал, Система**. Рабочая полка видна в верхней части любого экрана. При незавершённой проверке появляется кнопка **«Продолжить проверку»**.
- **Создание:** сканирование товарных ШК или артикулов с Enter, накопление партии, одно подтверждение. Повторный ШК означает ещё один физический экземпляр того же артикула. Нет этапа печати этикеток.
- **Запись RFID:** отдельный режим «ШК товара → свободный образец на текущей полке → запись уникального EPC → проверка чтением». Макет имитирует запись кнопкой «ДЕМО: записать EPC и проверить». **Физическая RFID-метка не программируется**. Автоматически выбирается только экземпляр **на рабочей полке** без EPC. Существующие EPC не перезаписываются.
- **Проверка:** только уникальные EPC. Товарный ШК не принимается как EPC. Повторы не засчитываются, неизвестные коды попадают в отдельный список. Ожидаемые и обнаруженные экземпляры фиксируются в снимке; последующие исправления не меняют исходные результаты.
- **Исправление чужих:** два честных действия — «Вернул физически на учётную полку» (учётное место не меняется) и «Оставил здесь — исправить учёт» (учётное место меняется). Для группы достаточно одного подтверждения. «Не найден» разбирается отдельно и не означает исключение.
- **Отбор по остаткам:** оператор самостоятельно вводит порог **строго меньше N метров** (например, 1 м). Система показывает артикулы и **каждый физический экземпляр** с полкой и EPC. Оператор отмечает фактически убранные образцы и подтверждает исключение. **Нулевой остаток ничего не удаляет автоматически**. Список разбит на страницы по 40, массовый выбор ограничен 300 экземплярами за раз.
- **Исключение:** без отдельной роли администратора, но с обязательным подтверждением необратимой операции. Исключённый образец сохраняет EPC и историю интервала привязки в данных, оставаясь неактивным.
- **Поиск и отчёты:** постраничные таблицы (40 и 30 строк), явные пустые состояния и переходы.
- **Без печати и принтера** на любом этапе.

## Быстрые сценарии проверки

1. **100 сканов:** «Операции» → «Создать образцы» → «Демо: добавить 100 товаров» → «Создать 100 образцов». На экране результата выберите «Перейти к записи RFID».
2. **Запись RFID:** «Операции» → «Записать RFID» → отсканируйте/введите `ART-0001` + Enter → «ДЕМО: записать EPC и проверить». Код EPC появится в демоданных; реальную метку это не изменит.
3. **Проверка полки:** выберите полку → «Проверить полку» → «Начать проверку» → введите один из EPC + Enter несколько раз → завершите. Повтор не увеличит счётчик.
4. **Чужие образцы:** для исходной полки `B-01-02` есть деморасхождения. «Операции» → «Исправить расхождения» → «Выбрать все» → «Вернул физически на учётную полку» либо «Оставил здесь — исправить учёт». Снимок проверки останется прежним.
5. **Не найден:** «Исправить расхождения» → «Не найдены» → выберите найденный после проверки образец → «Нашёл здесь». В историческом снимке он по-прежнему отсутствует; отдельно сохраняется новое наблюдение.
6. **Отбор по остатку:** «Отбор по остаткам» → порог `1` м → отметьте нужные физические экземпляры → «Подтвердить исключение выбранных». Подтверждайте только физически убранные образцы.
7. **Возврат в незавершённую проверку:** начните проверку → откройте «Артикулы» → нажмите «Продолжить проверку» в постоянной верхней панели.
8. **Перемещение:** «Операции» → «Переместить по артикулу / EPC» → считайте уникальный EPC → выберите новую полку → подтвердите.

## Автоматическая проверка

При наличии Node.js из этой папки выполните:

```powershell
node UI_PROTOTYPE_V10.test.cjs
```

Тесты не устанавливают зависимости и не обращаются к сети.

## Ограничения и задачи настоящего приложения

Это **интерактивный HTML-макет**, а не рабочее Windows-приложение. Нет интеграции с реальной 1С:УНФ (остатки в метрах вымышлены), SDK Chainway C5, физической записи EPC, чтения TID, проверки фактической записи на метку, офлайн-очереди C5, сервера, транзакций БД, многопользовательского доступа, полноценного неизменяемого аудита, защиты от сетевых повторов, резервного копирования и автоматического обновления каталога 10 000 товаров. Демо-операции и подтверждения в браузере не доказывают готовность этих механизмов. В боевой версии 1С используется **только для чтения**. Отдельная роль администратора и печать этикеток не предусматриваются.

При разработке настоящего приложения запись RFID должна включать резервирование уникального EPC сервером, запись через C5, обязательный read-back и атомарную фиксацию связки только после успешной проверки. Неуспешную запись следует показывать как ошибку, а не как завершённую маркировку.
