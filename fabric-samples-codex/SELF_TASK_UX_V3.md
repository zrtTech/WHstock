# SELF_TASK_UX_V3.md — задание ChatGPT и Codex на переработку интерфейса

**Статус:** задание сформировано; дизайн v3 НЕ реализован и НЕ согласован пользователем.
**Дата:** 2026-10-29.
**Основание:** критический разбор UI_PROTOTYPE_V2.html и переданный пользователем отчёт «Доработка интерфейса учёта образцов».
**Адресат:** ChatGPT (проектирование, интерактивный прототип, UX-проверка), затем Codex (реализация и проверка на реальном ПК).

## 1. Задача

Переделать интерфейс учёта физических образцов тканей для оператора с низкой компьютерной грамотностью. Отказаться от основного экрана «таблица администратора с пятью фильтрами». Основной сценарий: **выбрать/отсканировать полку → отсканировать образцы или товары → увидеть понятный результат → выбрать ОДНО действие → проверить → подтвердить → увидеть отчёт**.

Одна комната; Windows-компьютер и полки в нескольких шагах. Примерно 10 000 товаров; 100 последовательных сканов на создание партии; 50 и более неправильных мест за одну проверку. Сканер USB HID и Chainway C5 (Android UHF RFID/2D), интеграция с 1С исключительно на чтение.

## 2. Что нужно создать — обязательные файлы

1. **UI_PROTOTYPE_V3.html** — один автономный HTML-файл, полностью интерактивный, с реалистичными демоданными, работает локально без сервера и без зависимостей.
2. **UX_V3_SPEC.md** — описание экранов, состояний, ошибок, сканирования, доступности, правил массовых действий.
3. **UX_V3_REVIEW.md** — краткая инструкция, как пользователь проверит прототип: сценарии и ожидаемые результаты.
4. **UX_V3_CHANGELOG.md** — что изменилось относительно v2 и какие ошибки исправлены.
5. **CODEX_UX_V3_HANDOFF.md** — требования к нативной реализации, API, тестам и неизменяемым ограничениям; без выдачи демо за интеграцию.

Разместить файлы по одному в существующем репозитории, дать прямые ссылки на каждый; **не архив**. Не объявлять задачу выполненной без реально созданных и проверенных файлов.

## 3. Экран «Рабочая полка» — стартовый

- Вверху постоянно крупно показывать код **рабочей полки** (например B-01-02), её полное имя и понятную кнопку «Сменить полку».
- По умолчанию при запуске не выбирать новую полку автоматически наугад. Последняя подтверждённая полка может быть предложена, но требует ясного отображения.
- Четыре крупных сценария: «Добавить образцы», «Проверить полку», «Исправить места», «Убрать образцы». Рядом — краткие пояснения человеческим языком.
- Отдельно показывать результаты последней завершённой проверки, дату/время, источник и счётчики: обнаружено не на месте, не найдено, остаток товара 0. Нулевой остаток не равен удалению.
- Данные текущей полки и данные прошлой проверки не смешивать.

## 4. «Добавить образцы» — 100 сканирований

- Сначала явно выбрать или сканировать полку назначения. Она крупно закреплена.
- Сканировать 100 товарных штрихкодов подряд через USB HID Enter, без мыши и без всплывающего окна на каждое сканирование. После Enter поле готово к следующему скану.
- Один скан товарного ШК означает **один новый физический образец**; два одинаковых скана означают два экземпляра, но повтор виден и исправляем.
- Показать крупный счётчик «Отсканировано 100», компактную очередь: товар, артикул, количество, ошибки, повторы. Возможность изменить количество, удалить ошибочную строку.
- Нераспознанные/неоднозначные коды блокируют создание до исправления.
- Пока оператор сканирует, **никакие образцы не создаются**.
- При смене полки с непустой очередью — предупреждение о переназначении всей партии.
- Последний шаг: отдельная большая кнопка «Создать 100 образцов на полке B-01-02»; предпросмотр; итог «Создано 100 из 100» + коды + возможность печати только при проверенном принтере.
- Повтор запроса после обрыва связи не создаёт дубли: стабильный batchRequestId и payloadHash.

## 5. «Проверить полку»

- Начало новой проверки — заморозить ожидаемый набор образцов для выбранной полки.
- Принимать наблюдения от C5/сканера, показывать прогресс, неизвестные EPC, дубли чтений и источник/время.
- Сканирование/наблюдение **никогда автоматически не меняет учётную полку**.
- Только после завершения проверки допустимо считать ожидаемые, но не найденные образцы «не найдены». До этого статус «ещё не проверен».
- После завершения показать три простых списка: «На месте», «Чужие на полке», «Не найдены». Кнопка «Исправить 50 чужих» открывает список с сохранённым контекстом проверки.
- Отсутствие не означает удаление.

## 6. «Исправить места» — 50+ образцов

- Начальный выбор задачи: «Найдены на этой полке, но числятся на другой» или «Числятся здесь, но не найдены».
- Компактная таблица с крупными читаемыми строками и колонками: чекбокс, код, название, учётная полка, где обнаружен, статус, дата наблюдения. Технические фильтры — в сворачиваемом блоке «Дополнительный поиск», не в главном рабочем пути.
- Одна заметная кнопка «Выбрать все 50»; всегда крупно показывать «Выбрано N из M». Выбор должен относиться к явно показанному отфильтрованному набору, без скрытых записей.
- Отдельные, **не смешанные** сценарии:
  - «Оставить здесь — исправить учёт»: целевая полка равна подтверждённой рабочей полке; изменить место выбранных образцов на неё.
  - «Перенести физически»: показать, куда они числятся; не изменять учётное место, пока пользователь не подтвердил фактический перенос/новое место.
  - «Переместить на другую полку»: оператор отдельно сканирует/выбирает целевую полку, видит её крупно, подтверждает действие.
- Для каждой операции: предпросмотр количества и направлений перемещения, подтверждение, результат. Без повторного сканирования уже идентифицированных образцов.
- Нельзя использовать старое наблюдение как актуальное без показа времени и контекста; старые данные не выдавать за текущие.
- При конфликте версий не менять молча часть партии.

## 7. «Убрать образцы» — отдельный опасный сценарий

- Сначала выбрать кандидатов по рабочей полке, поиску или справочному признаку «остаток 1С = 0».
- Остаток 1С = 0 — **не команда удаления**. Показывать актуальность данных остатков, склад/агрегацию, если проверены.
- Подтверждение удаления показывает точное число и список кодов, объясняет: «Исключить из активного учёта. Вернуть через интерфейс нельзя. История останется».
- Удаление не соседствует с кнопкой перемещения на основном экране.
- Сохранять tombstone и неизменяемое событие аудита. Не удалять строки из базы физически.
- Роль/дополнительное подтверждение удаления — открытый вопрос, не выдумывать разрешения.

## 8. Доступность и простота

- Текст рабочих элементов преимущественно 15–16 px; важные коды полок 24–32 px; кликабельные цели минимум около 44 px по высоте; адекватный контраст.
- Минимум терминов EPC, snapshot, version, batchRequestId в интерфейсе оператора. Эти понятия остаются во внутренней реализации и техническом журнале.
- На каждом шаге **одно главное действие**, «Назад» и «Отмена» без потери данных без предупреждения.
- Сканер-first: видимый статус «Готов к сканированию», автоматический возврат фокуса после скана, звуковой/цветовой сигнал без опоры только на цвет; поддержка ручного ввода.
- Защита от случайного двойного Enter, неверного типа штрихкода (товар/образец/полка), изменения рабочей полки при незавершённом действии.
- Таблицы остаются для списков, но не заменяют сценарии.
- После действия показать результат с числом обработанных, ошибок и дальнейшим шагом; при сетевой неопределённости не показывать ложное «успешно».

## 9. Безопасность, API и данные

- **1С read-only**: каталог/штрихкоды/остатки только при подтверждённом способе чтения. Никаких документов, записей или SQL-модификаций в рабочей 1С.
- Уникальный sampleCode для каждого экземпляра, даже если productId один; EPC уникален среди активных привязок; история привязок интервальная.
- Все изменения Samples и AuditEvents — в одной транзакции. Идемпотентность requestId + deviceId + payloadHash. Оптимистические версии.
- **Не принимать буквально из отчёта три новых URL** /samples/bulk-create, /samples/bulk-move, /samples/bulk-remove: в существующем BULK_API_CONTRACTS.md уже определены /api/v1/sample-batches и /api/v1/sample-operations. Сохранить единый набор endpoint'ов, не создавать дублирующий API.
- **Не смешивать частичный результат и атомарность**: по действующему контракту массовые CREATE/MOVE/DELETE атомарны. При конфликте одной строки — весь пакет отклонён, ни один объект не изменён; UI показывает ошибки по строкам и предлагает исправить. Формат succeeded[]/failed[] допустим только при явно согласованной политике частичных операций; по умолчанию её НЕТ.
- Офлайн C5: сохранять исходный requestId и неизменяемый payload до подтверждения сервера; retry не дублирует события.
- Проверить реальный SDK Chainway, опубликованные OData объекты 1С, USB HID, TLS, бэкапы на машине до реализации; не выдумывать проверенные интеграции.

## 10. Демонстрационные данные и интерактивность v3

HTML-макет должен позволять руками пройти:
1. Выбор полки B-01-02.
2. 100 сканирований (кнопка «Загрузить 100» как быстрый демонстрационный сценарий, но также ручной ввод с Enter).
3. Повтор одного товара и неизвестный код.
4. Подтверждение партии; отчёт; просмотр созданных экземпляров.
5. Проверка полки: 50 чужих, 8 не найденных.
6. «Выбрать все 50» → «Оставить здесь — исправить учёт» → предпросмотр → итог.
7. Отдельный сценарий «Переместить на другую полку» с явным сканированием целевой полки.
8. Отбор образцов по нулевому остатку 1С → выбор 20 → подтверждение удаления → итог.
9. Симуляция конфликта версии и неопределённого сетевого результата, без ложного успеха.
10. Клавиатурная навигация и восстановление фокуса сканирования.

Все кнопки, видимые как рабочие, должны реально работать в демо; никакой записи в 1С/реальную базу.

## 11. Проверка качества перед показом пользователю

- Пройти сценарии 1–10, проверить численные счётчики и изменения после каждого действия.
- Проверить, что «Открыть» действительно открывает карточку, либо переименовать кнопку согласно действию.
- Проверить контраст, масштабирование Windows 125/150%, разрешение 1366×768 и 1920×1080, отсутствие критической горизонтальной прокрутки.
- Провести короткий пользовательский тест с человеком, который не знает интерфейс: без объяснения попросить выбрать полку, добавить 5 образцов, исправить 3 чужих, убрать 2. Зафиксировать ошибки/зависания; до этого не заявлять, что UX подтверждён.
- Проверить, что нет удаления по нулевому остатку, наблюдение не меняет учёт, удаление не восстановимо через UI.
- Код HTML/CSS/JS структурировать; не писать огромные нечитабельные обработчики, не подменять функциональность визуальной имитацией.

## 12. Открытые решения, которые нельзя додумывать за пользователя

1. Что чаще происходит с чужими образцами: оставить там, где нашли, или физически разнести по учётным местам? **Пока реализовать оба сценария, не выбирать один автоматически.**
2. Как именно маркируются и печатаются этикетки; какое оборудование реально подключено?
3. Нужна ли отдельная роль на удаление?
4. Откуда и по какому складу брать остатки 1С? Если это не проверено, пометить «данные недоступны», а не рисовать ноль.

## 13. Definition of Done

**Этап 1 — прототип:** пять файлов из раздела 2 существуют, HTML открыт и проверен, все десять демосценариев выполняются, пользователь получил прямые ссылки и может проверить макет. До его обратной связи v3 — «предложение», не утверждённый дизайн.

**Этап 2 — реализация Codex:** только после согласования макета и проверки Windows/1С/C5; нативный Windows UI, серверный API, миграции, автоматические и аппаратные тесты, безопасная установка и восстановление. Не смешивать готовность прототипа с готовностью приложения.
