# Решения, допущения и вопросы

## Зафиксировано для MVP
- Приложение отдельное от 1С; данные из 1С только читаются.
- Три операции над образцом: создание, перемещение, окончательное удаление.
- Проверка места — наблюдение; автоматически учёт не исправляет.
- Нативный Windows UI, а не обязательный браузер.
- Отдельная SQL Server БД.
- Один backend обслуживает Windows и C5.
- Уникальный код физического образца обязателен; товарный ШК не считается уникальным кодом экземпляра.

## Рабочие предположения (проверить до production)
- Python 3.12 + PySide6 + FastAPI + SQL Server — выбранный стартовый стек. Смена на C# WPF допустима только после решения заказчика, без изменения бизнес-контрактов.
- Установлен SQL Server, но права создания новой БД и лицензирование пока не проверены.
- Доступен read-only интерфейс 1С: OData/HTTP или экспорт; конкретные имена сущностей неизвестны.
- Исходники существующего APK Chainway C5 и формат его API не предоставлены; повторное использование не гарантировано.
- Принтер этикеток и его язык команд неизвестны.
- Режим USB HID для конкретного стационарного ШК-сканера нужно проверить.

## Открытые вопросы для настройки, не повод блокировать локальный MVP
1. Где будет работать backend и какой адрес LAN/сертификат?
2. Какой конкретно USB-сканер: HID или COM?
3. Какие принтер и формат этикетки?
4. Есть ли исходники C5-клиента и SDK RFID?
5. Какие реквизиты 1С служат устойчивым ID товара и какие endpoint опубликованы?
6. Какие роли и сколько операторов?
7. Нужен ли импорт текущих образцов/мест из прежнего расширения 1С?
8. Нужно ли показывать остатки ткани из 1С или достаточно каталога?
9. Должно ли создание образца уменьшать складской остаток ткани в 1С? В этой архитектуре — НЕТ. Если требуется ДА, нужна отдельная постановка на учёт складских движений.

## Запрет на выдумывание
Codex не должен изобретать названия OData entity sets, RFID SDK methods, структуру существующего APK или адреса серверов. До проверки использовать тестовые адаптеры и явно показывать «интеграция не настроена».
