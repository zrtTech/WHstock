# Макет v11 — упрощённый интерфейс и QR места

**Открыть:** `UI_PROTOTYPE_V11.html` (скачать Raw и открыть в Edge/Chrome).  
**Проверить:** `node UI_PROTOTYPE_V11.test.cjs` — Node.js, без npm.

## Изменения по UX-аудиту

- Постоянные основные разделы: «Склад», «Работа на полке», «Найти товар», «Аналитика», «Журнал», «Система». Оператор начинает с артикула/товарного штрихкода, а внутренний ID нужен только для различения нескольких физических экземпляров.
- **Запись RFID и привязка EPC к товару полностью на ТСД Chainway C5.** В Windows нет экрана записи EPC, поля ручной привязки или кнопки «Записать». Есть экран просмотра «RFID с C5» и техническая имитация приёма готового события.
- Входящее демособытие C5 содержит `eventId`, `sampleId`, `barcode`, `epc`, `readBackEpc`, `confirmed`, `expectedVersion`. Приём проверяет совпадение товарного ШК, контрольное чтение, формат EPC, уникальность активной привязки, версию записи и идемпотентность. При ошибке ничего не привязывается. Для нескольких образцов одного артикула **обязателен однозначный ID экземпляра**, предоставленный протоколом ТСД; по одному товарному ШК выбирать экземпляр нельзя.
- **QR места** — отдельная необязательная функция на экране «Работа на полке». Выбираются полка и число наклеек (1–20). Генерируется локальный QR формата `RACK:B-01-02`, плюс человекочитаемый номер полки. Наклейка предназначена для физического образца, но **не заменяет его товарный ШК или RFID** и не является уникальным идентификатором образца.
- При перемещении образца старую наклейку QR места нужно заменить или снять. Это эксплуатационный риск; приложение не должно принимать QR места за доказательство текущего фактического положения.
- Нет обязательной печати индивидуального ID образца. Создание образцов не зависит от наличия принтера.

## Исследование и разработка QR-печати

Перед использованием на складе проверить: тип и ширину этикеток, разрешение/драйвер принтера, размер и контраст QR, сканирование USB-сканером и C5, сохранность наклейки на ткани/образце, обновление QR при перемещении, различие между «адрес полки на образце» и «адрес полки на стеллаже». В макете используется локальный QR версии 1-L (ASCII), SVG и стандартный диалог печати браузера. Физическая печать и считывание **не проверены**.

## Ограничения

Это **браузерный UX-макет**, не установленное Windows-приложение. Нет реального 1С:УНФ, C5, API, фоновой службы, SQL Server, печати на оборудовании или неизменяемого серверного аудита. Сохранение демоданных — в `localStorage`. Приём C5 симулируется из технического раздела, реальная синхронизация не подключена. Макет v11 сделан на упрощённой ветке v9 для проверки пользовательского сценария; он **не заменяет** все более глубокие сценарии и тесты v7/v10 (офлайн-очередь, расширенный аудит, идемпотентные складские операции). Эти функции должны быть перенесены в нативную реализацию, а не считаться готовыми по v11.

## Ключевые UX-риски и следующие шаги

1. Критический: не путать QR места с уникальным EPC образца; не менять место автоматически после сканирования QR.
2. Критический: при нескольких экземплярах одного артикула протокол C5 должен передавать идентификатор конкретного экземпляра и подтверждение контрольного чтения.
3. Высокий: на реальном складе проверить полный цикл «создать → связать на C5 → получить данные → проверить полку → переместить → заменить QR места» с оператором без подсказок.
4. Высокий: для Windows-программы обеспечить понятные статусы офлайн/ожидание/ошибка синхронизации и повтор отправки без дублей.
5. Средний: измерить число действий и время сценариев для одного оператора; убрать лишние технические поля с основных экранов.
