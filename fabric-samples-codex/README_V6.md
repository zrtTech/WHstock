# Интерактивный макет учёта образцов v6

**Файл:** `UI_PROTOTYPE_V6.html` — один автономный HTML-файл. Открывается локально в браузере Windows без установки библиотек и без сервера. Это **тест интерфейса**, не готовая складская система.

## Запуск

1. Скачайте `UI_PROTOTYPE_V6.html` из репозитория через кнопку **Raw → Save As** (сохранить как `.html`, не `.txt`).
2. Откройте файл в Microsoft Edge или Chrome.
3. В начале есть демоданные: **140 товаров, 80 образцов, 4 полки**. На полке **B-01-02** уже есть завершённая проверка: **50 чужих, 8 не найдены, 12 на месте**.
4. Вся информация вымышленная. Макет **не подключается** к 1С, C5, API, SQL Server, принтеру или реальному складу.
5. Изменения сохраняются в localStorage, если браузер это разрешает. Для переноса данных используйте «Система / C5 → Экспортировать JSON». Сброс: «Система / C5 → Сбросить демоданные».

## Что исправлено по аудиту v5

- **Склад** больше не зависит от текущей полки; KPI кликабельны, полки без проверок фильтруются, указаны даты проверок.
- **Работа на полке** содержит создание, прямое перемещение, проверку и исключение. Исправление расхождений появляется только после завершённой проверки.
- **Выбор полки** сканированием `RACK:B-01-02` или из списка применяется сразу. При набранной партии программа спрашивает разрешение на переназначение.
- **Создание партии**: скан товара + Enter автоматически добавляет строку, артикул и ШК одного товара суммируются, можно создавать 100+ образцов. Новые экземпляры получают уникальные `S-...` и статус «Ожидает маркировки».
- **Маркировка**: печать *текстового макета* этикеток и подтверждение наклейки сканированием уникального кода; незавершённую маркировку можно возобновить.
- **Проверка**: сканы USB-HID (Enter) принимаются без кнопки, повтор не увеличивает число уникальных, неоднозначный товарный ШК требует уточнения, неизвестные сканы не теряются. Завершение только вручную.
- **Неизменяемые результаты**: каждый сеанс хранит собственные `expected` и `observations`. Новые проверки не переписывают историю старых, а решения по проблемам привязаны к `inspectionId`. Позднее обнаружение записывается отдельным событием, а не задним числом в старый сеанс.
- **Расхождения**: чужие — «Закрепить здесь», «Куда вернуть», «Другая полка»; не найденные — «Нашёл здесь», «Нашёл в другом месте», «Убрать». Статус «в поиске» возникает автоматически.
- **Массовые действия**: выделение + контекстная команда; подтверждение для массового изменения мест и исключения; одна явно выбранная запись «Закрепить здесь» исправляется в один клик.
- **Навигация**: «Назад» возвращает в источник операции, в том числе при удалении из списка не найденных. Для создания, перемещения и исключения есть явная отмена.
- **Поиск**: по экземпляру, EPC, товарному ШК, артикулу, названию и полке. Удалённый образец сохраняется как tombstone и может быть найден по коду.
- **EPC**: в карточке есть демонстрационная привязка, контроль уникальности активного EPC и история интервалов.
- **C5**: демонстрационная офлайн-очередь событий, имитация отправки и дедупликация `eventId`. Пока очередь не отправлена, проверка не завершается.
- **Журнал**: операции сохраняют идентификаторы образцов, время, `requestId`, место до/после в описании; в демо он сохраняется между обновлениями браузера.
- **Отчёты**: глобальный поиск, переход к экземпляру/проблеме, 30 строк на страницу. «Система / C5 → Каталог 10 000 (тест)» расширяет каталог для нагрузочной проверки.
- **Сбой сети / конфликт**: на подтверждении можно смоделировать `VERSION_CONFLICT` и неопределённый результат; повтор сохраняет тот же `requestId`. Демо-операции записываются в журнал запросов.

## Что проверить вручную

1. **50 чужих:** «Склад → B-01-02 → Работать → Разобрать чужие → Выбрать все 50 → Закрепить здесь → Подтвердить». Открытых чужих станет 0, но в исходном историческом сеансе останется 50.
2. **8 не найдены:** «Разобрать не найденные → Выбрать все 8 → Нашёл 8 здесь → Подтвердить». Открытых пропусков станет 0. Затем начните новую проверку B и завершите без сканов: получите **20 не найденных**, не 12.
3. **Поток сканирования:** «Проверить полку → Начать → S-000001 + Enter → S-000002 + Enter». Оба кода появляются без кнопки фиксации.
4. **Прямое перемещение:** «Работа на полке → Переместить → S-000001 + Enter → D-03-01 → Переместить». История и место обновятся.
5. **Партия:** «Добавить образцы → Загрузить демо: 100 товаров → Создать 100 → Подтвердить → Маркировка». Затем в поле маркировки `S-000300` + Enter.
6. **Офлайн:** «Проверить полку → Начать → Система / C5 → Перевести C5 в офлайн → S-000001 → Сканировать с C5». После возвращения в сеть отправьте очередь и завершите проверку.
7. **Навигация:** из списка «Не найдены» откройте исключение, нажмите «Назад без изменений» — вернётесь в правильный список, без удаления.
8. **10 000 товаров:** «Система / C5 → Каталог 10 000 (тест) → Отчёты → Без образца». Проверить поиск и постраничный вывод.

## Автоматическая проверка

Рядом лежит `UI_PROTOTYPE_V6.test.cjs`. При установленном Node.js запустите в каталоге с двумя файлами:

```powershell
node .\UI_PROTOTYPE_V6.test.cjs
```

Тесты не используют npm, 1С, C5 и сеть. Они проверяют инварианты и сценарии демонстрационного JavaScript. Отдельно нужно визуально пройти интерфейс в браузере.

## Границы и недоделанные интеграции

- **Это не реализация производственного приложения.** localStorage не заменяет SQL-транзакции, независимый API, авторизацию, резервное копирование или настоящую идемпотентность сервера.
- **C5 — имитатор.** SDK Chainway, UHF-инвентаризация, Bluetooth/Wi-Fi, TLS и фоновые службы Windows не подключены. Реальный C5 должен быть проверен Codex на устройстве.
- **1С — не подключена.** Каталог и остатки демонстрационные. Никаких записей в 1С макет не выполняет.
- **Этикетки текстовые.** Макет печати не генерирует настоящий сканируемый ШК и не управляет принтером. Этот шаг требует выбора формата этикетки и теста реального сканера/принтера.
- **Сетевые ошибки моделируются.** Для боевого кода нужны транзакции, аудит, `requestId + payloadHash`, `expectedVersion`, проверки конфликта и атомарность на сервере.
- **Нагрузка 10 000** относится к каталогу в браузере; это не тест скорости реального SQL/API и не проверка всех операций с 10 000 физическими экземплярами.

## Для Codex

Использовать v6 как **UX-эталон для согласования**, а не копировать его монолитный JavaScript в боевой код. Производственную систему реализовать по отдельным модулям (домен, хранилище, API, интеграции, Windows UI, C5), с миграциями, тестами, аудитом и проверкой оборудования. Сначала закрыть бизнес-вопросы маркировки и удаления, затем реализовать реальные контракты и проверить на Windows. См. `UX_AUDIT_V5.md`.
